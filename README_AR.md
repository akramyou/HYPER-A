# Hyper Dammam — نسخة إصلاح أولية

هذا الأرشيف يحتوي على إصلاحات أولية لمشروع Flutter لإدارة المخزون. لم يتم تأكيد نجاح بناء APK داخل بيئة إعداد هذا الملف لأن Flutter وDart غير مثبتين هنا؛ يجب انتظار نتيجة GitHub Actions قبل اعتبار البناء ناجحاً.

## الإصلاحات التي أُجريت

- إعادة دعم قراءة ملفات Excel من نوع `.xlsx` باستخدام حزمة `excel`، إلى جانب CSV.
- تصحيح فك ترميز ملفات CSV إلى UTF-8 للمساعدة في الحفاظ على النص العربي.
- إصلاح استخدام نتيجة `isConfigured()` غير المتزامنة داخل واجهة الاستيراد.
- حفظ معرّف الفرع والمنظمة في مفاتيح الإعداد المنفصلة، وتمرير الفرع مباشرة عند البحث عن الصنف، وتجنب البحث باستخدام كود فارغ.
- جعل ترحيل قاعدة البيانات يتحقق من وجود عمود `extra_data` قبل إضافته.
- إضافة delegates الترجمة الأساسية للعربية والإنجليزية.
- جعل إعداد توقيع Release لا يفشل إذا لم يوجد مفتاح خاص: تُبنى حينها نسخة اختبار موقعة بمفتاح debug.
- إضافة اختبارات أولية لكشف أعمدة التقارير وتفسير تواريخ الانتهاء.
- تحديث GitHub Actions بحيث ينشئ ملفات Gradle Wrapper الناقصة من قالب Flutter داخل بيئة CI ثم يبني ويرفع APK كـ Artifact.

## إنشاء APK عبر GitHub

1. ارفع محتويات مجلد المشروع إلى مستودع GitHub مع الحفاظ على بنية المجلدات.
2. افتح تبويب **Actions**.
3. شغّل سير العمل **Build Flutter APK** أو انتظر تشغيله بعد push.
4. لا تعتبر العملية ناجحة إلا إذا انتهت جميع خطوات الاعتماديات والتحليل والاختبارات والبناء بعلامة خضراء.
5. افتح تشغيل Workflow الناجح ونزّل `hyper-dammam3-apk` من قسم **Artifacts**.

## البناء المحلي على Windows

إذا كنت ستبني المشروع على جهازك، افتح PowerShell من مجلد المشروع ونفّذ `powershell -ExecutionPolicy Bypass -File .\tools\prepare_gradle_wrapper.ps1` مرة واحدة لاستكمال ملفات Gradle Wrapper الناقصة. بعد ذلك نفّذ `flutter pub get` ثم `flutter analyze` و`flutter test` و`flutter build apk --release`.

## التوقيع

إذا لم يُضف ملف `android/key.properties` ومفتاح توقيع دائم، فإن APK الذي ينتجه Workflow هو نسخة اختبار موقعة بمفتاح debug. يمكن تثبيته للاختبار، لكنه ليس مناسبًا كتوقيع إصدار إنتاجي دائم ولا يضمن إمكانية تحديثه لاحقًا بمفتاح مختلف. لا تُرفع مفاتيح التوقيع الخاصة إلى المستودع.

## ملاحظة حول Gradle Wrapper

الأرشيف الأصلي لم يتضمن `gradlew` و`gradlew.bat` و`gradle-wrapper.jar`. سير العمل في GitHub ينشئها أثناء البناء من قالب Flutter، ويثبت Gradle 8.3. للبناء المحلي المباشر، يلزم استكمال ملفات Gradle Wrapper قبل تشغيل `flutter build apk --release`.

## حدود التحقق

تم تعديل الملفات وفحصها ساكنًا، وأُضيفت اختبارات، لكن لم يتم تشغيل `flutter pub get` أو `flutter analyze` أو `flutter test` أو `flutter build apk --release` في بيئة إعداد الأرشيف. نتائج GitHub Actions هي التي ستحدد ما إذا كانت هناك أخطاء أخرى تتطلب إصلاحًا.

## الشعار وإعداد بناء Android

- الشعار الرسمي داخل التطبيق: `assets/images/hyper_logo.png`.
- جرى إدخال الشعار في لوحة التحكم، وأيقونة Android، وشاشة البداية (بموارد منفصلة ملائمة لكل استخدام)، مع استخدام خلفية عاجية فاتحة للحفاظ على وضوح الألوان.
- يحتوي `android/build.gradle` على توافق رجعي للمكتبات الإضافية القديمة التي لا تعلن `namespace`. يفضّل تحديث المكتبة المتسببة إلى إصدار حديث يدعم Android Gradle Plugin 8 عند التأكد من اسمها، ثم إزالة حل التوافق المؤقت إذا لم يعد مطلوبًا.
- يلزم تشغيل GitHub Actions لتأكيد نجاح `flutter analyze` والاختبارات وبناء APK. لم يتم تنفيذ بناء Flutter فعلي ضمن بيئة إعداد هذه الحزمة.
