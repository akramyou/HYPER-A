# هايبر | نظام إدارة المخزون وتواريخ الصلاحية

مشروع Flutter جديد مبني وفق المواصفات الفنية المرفقة وعينة تقرير `DAMMAM-3 06-10-2026.xlsx`، مع قاعدة بيانات SQLite محلية ومخرج Android APK موجّه لمعمارية ARM64.

## الوظائف المضمنة

- واجهة عربية RTL وشعار هايبر ولوحة تحكم.
- إدارة الأصناف والبحث في الأسماء والأكواد وموقع التخزين، مع حد إعادة طلب اختياري لكل صنف؛ الحقل الفارغ يستخدم حد الفرع الافتراضي.
- مرشحات المخزون تستخدم حد إعادة الطلب الخاص بالصنف عند تعريفه، وإلا تستخدم الحد الافتراضي العام. الترحيل إلى قاعدة البيانات الإصدار 3 يضيف الحقل دون إسقاط السجلات القائمة.
- إدارة دفعات متعددة لكل صنف، لكل دفعة تاريخ إنتاج وانتهاء وكمية مستقلة.
- التنبيهات حسب حالة كل دفعة: منتهية، ≤7 أيام، ≤30 يومًا، 31–60، 61–90، آمنة، وتنبيه المخزون المنخفض.
- استيراد XLSX وCSV مع اقتراح ومراجعة تعيين الأعمدة، وتاريخ مستقل لكل لقطة تقرير.
- دعم رؤوس التقرير: `BRANCH_ID`, `ORG_CODE`, `APPS_CODE`, `POS_CODE`, `DESCRIPTION`, `ARB_DESC`, `UOM`, `WH_STOCK`, `BR_STOCK`, `SOLD_STK`, `WH_LOC_CODE`, `FLYER_ITEM`.
- قاعدة عمل الاستيراد الحاسمة: الأصناف الموجودة تُحدّث حقول الكميات الثلاثة فقط (`wh_stock`, `br_stock`, `sold_stk`). لا يلمس الاستيراد جداول الدفعات أو تواريخ الإنتاج والانتهاء. تُقبل قيم المخزون السالبة كما وردت في تقرير المصدر.
- سجل عمليات ونسخ احتياطي واستعادة من ملف JSON.
- رسوم تحليل وتقارير قابلة للمشاركة.
- أدوات على الجهاز للتعرف على النصوص (OCR)، وقراءة الباركود/QR، وتصنيف الصور، باستخدام إضافات ML Kit المتخصصة بدل إضافة ML Kit الجامعة لتجنب إدخال وظائف غير لازمة في الاعتماديات.
- مسار CI في GitHub Actions لتثبيت الاعتماديات والتحليل والاختبارات وبناء Release APK لمعمارية ARM64 وتحليل الحجم.

## تشغيل المشروع محليًا

يتطلب Flutter 3.24.5 وAndroid SDK وJDK 17 (ويمكن تحديث الإصدار لاحقًا بعد اختبار التوافق).

```bash
flutter doctor
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64 --analyze-size
```

المخرج المتوقع:

`build/app/outputs/flutter-apk/app-release.apk`

## بناء GitHub Actions

ارفع محتويات هذا المجلد إلى جذر المستودع. اذهب إلى Actions ثم `Hyper Inventory - Android ARM64 APK`. يعمل تلقائيًا عند الدفع إلى `main` أو `master`، كما يمكن تشغيله يدويًا عبر `Run workflow`.

بعد نجاح جميع الخطوات، نزّل Artifact المسمى `hyper-inventory-arm64-apk`. يحتوي على APK وتقرير تحليل الحجم.

ملفات Gradle Wrapper غير المتوفرة في بيئة المصدر تُنشأ في بيئة GitHub Actions عند الحاجة. ويُنشأ `android/local.properties` في الـrunner، ولا يُرفع إلى GitHub.

## قرارات تصميم مهمة

- لا يوجد خادم أو تسجيل دخول أو مزامنة سحابية؛ البيانات التشغيلية محلية على الجهاز.
- لا يمنح استيراد تقرير المخزون أي صلاحية لتعديل تواريخ الصلاحية أو الإنتاج. هذه التواريخ تُدار في جدول `item_batches` بشكل مستقل.
- يتم منع تكرار الصنف بمفتاح `(apps_code, pos_code, branch_id)`.
- قيم `SYS_CAL_QTY` و`MOD_QTY` في عينة التقرير ليست حقول مخزون معتمدة للاستيراد؛ تحفظ ضمن `extra_data` للأصناف الجديدة إذا لم تُعيّن يدويًا.
- اسم الحزمة الخاص بقراءة XLSX هو `excel` (وليس `xlsx` غير المتاح كاعتماد بهذا الاسم على pub.dev).
- حل تعارض ML Kit مثبت في هذه النسخة: `google_mlkit_text_recognition: ^0.15.0` مع `google_mlkit_commons: ^0.11.0`. لا تُعد إلى `google_mlkit_text_recognition ^0.14.0` مع commons 0.11؛ فهذا تعارض يحول دون `flutter pub get`.
- إضافات ML Kit لا تعمل على الويب، وإنما على Android/iOS. OCR المستخدم هنا مبني على النص اللاتيني؛ وهو لا يضمن قراءة النص العربي على العبوات. يجب تأكيد أي تاريخ يقترحه OCR يدويًا.
- تصنيف الصور يعطي وصفًا عامًا للصورة، وليس معرفًا تجاريًا مضمونًا للمنتج. قراءة الباركود لا تستخرج تاريخ الصلاحية إلا إذا كان التاريخ مضمّنًا في صيغة الباركود المقروءة.
- ملف Release الذي ينشئه سير العمل موقع بمفتاح debug لتجربة التثبيت فقط. للنشر الرسمي أو تحديثات طويلة الأجل، يجب إعداد keystore دائم وآمن، وعدم رفعه للمستودع.

## الاختبارات

تحتوي مجلدات `test/` على اختبارات لتفسير التواريخ، والتعرف على أعمدة التقرير، واستيراد قاعدة البيانات مع التحقق من أن تاريخ الدفعة يبقى كما هو عند تحديث الكميات. لا تعتبر النسخة معتمدة للإنتاج حتى تنجح GitHub Actions وتُجرّب الوظائف على جهاز Android حقيقي، وبالأخص XLSX وOCR والباركود والنسخ الاحتياطي والاستعادة.

## حدود النسخة التي يجب التحقق منها قبل اعتماد الإنتاج

- التنبيهات الحالية تُحسب وتُعرض داخل التطبيق عند فتح شاشة التنبيهات؛ لم تتم إضافة جدولة إشعارات Android تعمل دوريًا في الخلفية والتطبيق مغلق. إذا كانت التنبيهات الفورية خارج التطبيق شرطًا تشغيليًا، فيجب تنفيذها واختبارها كمرحلة مستقلة.
- OCR يستخدم النص اللاتيني في إصدار ML Kit المختار. لا يُعتمد عليه لقراءة الملصقات العربية؛ يجب اختبار ملصقات المنتجات الفعلية وتحديد محرك OCR مناسب للعربية إذا لزم.
- هذا المستودع مصدر Flutter، وليس APK مبنيًا ومختبرًا. يلزم نجاح GitHub Actions ثم تثبيت APK وتجربة XLSX/CSV، وتعدد الدفعات، والنسخ الاحتياطي والاستعادة، وقراءة الكاميرا على جهاز ARM64 قبل استخدامه في المخزون الفعلي.


## مراجع تصميم التقارير (بحث خارجي باللغة الإنجليزية)

استُلهمت بعض أنماط التقارير من التوثيق العام لمنتجات إدارة المخزون، دون نسخ شيفرة أو افتراض بيانات غير متوفرة:

- Zoho Inventory: تقرير Inventory Turnover by Quantity يعرض نطاق التاريخ، ومخزون بداية/نهاية الفترة، والكمية المباعة، ومتوسط المخزون، ومعدل الدوران وأيام الدوران. https://www.zoho.com/us/inventory/help/reports/inventory-reports.html
- Lightspeed Retail: تقرير Sell-through يستخدم الفترة الزمنية، ومتوسط البيع اليومي، ونسبة البيع من المخزون وأيام التغطية، مع مرشحات المنتجات. https://x-series-support.lightspeedhq.com/hc/en-us/articles/25534083755675-Using-the-sell-through-inventory-report

تُحسب نتائج Hyper من اللقطات التاريخية المحلية، وتظل تقديرية إن لم يحدد مصدر التقرير معنى `SOLD_STK` بدقة. لا تعرض النسخة أرباحًا أو تكلفة مخزون أو قيمة دوران مالية؛ لأن عينة المصدر لا تتضمن أسعار التكلفة/البيع.
